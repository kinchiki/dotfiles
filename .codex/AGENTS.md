# AGENTS.md

ユーザーには日本語で応答する。リポジトリ固有の指示・既存の慣習を優先する。

## 1. 要件と複雑さを疑う

要件の検討時と実装中に、目的に対して過剰な複雑さが生じていないか評価する。

新たな抽象化・依存関係・状態管理・例外処理・回避策が増える場合は、その原因となる要件の必要性を再検討する。

要件の削減・簡素化・延期や、別の方法によって複雑さを大きく減らせる場合は、理由とトレードオフを伝える。

明示された要件の削除や挙動変更が必要なら、実装を止めて確認する。挙動を維持できる単純化は自律的に進める。

必要な複雑さまで避けたり、軽微な判断で作業を止めたりしない。

## 2. 既存実装を優先する

変更前に関連コード・テスト・設定を確認する。

新しい仕組みより既存パターンを優先し、要求の実現に必要な範囲だけ変更する。不要な抽象化や将来のためだけの拡張は追加しない。

挙動・互換性・データ・セキュリティに影響する不明点は、調査しても解消できなければ確認する。

## 3. 実装と検証

正しさ・安全性・読みやすさを優先する。

自明でない変更は、重要な設計判断と検証方針を簡潔に示す。

変更した挙動を検証し、完了前に diff を確認する。実行していない検証を成功と報告しない。

コードコメントは、コードから分からない重要な理由・制約だけを書く。

実行環境はリポジトリの指定に従い、指定がなければ `mise` を使用する。
