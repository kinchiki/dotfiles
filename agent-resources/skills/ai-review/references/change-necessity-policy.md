# Change Necessity Policy

計画、実装、コードレビュー、PR レビュー対応で、追加の対策や改善提案、指摘への対応が必要かを判断するときに使う。

## 判断基準

指摘が論理的に正しいかと、対応が必要かを分けて判断する。
現在の要件と実際の利用条件に照らし、次を確認する。

- 問題が起きる具体的な条件と、その条件が成立する見込み。
- 起きたときの影響と、現在の要件を満たすうえでの支障。
- 既存のコード・制約による防止やテストによる検証が、指摘の発生条件にも適用されるか。
- 修正の効果と、追加する処理・テスト・運用の負担や複雑性。

仮定を重ねた懸念、効果の乏しい整理、既存の保証で対処済みの問題は見送り候補とする。
発生見込みや影響が小さく、修正の負担や複雑性に見合わない予防策も見送り候補とする。
低確率でも重大な安全性・データ損失などの影響がある問題や、明確な要件違反は個別に評価する。
誤字などの軽微な誤りも、誤案内や仕様との不一致などの実害と修正負担に応じて修正候補にする。

## 評価

| 評価 | 判断 |
|------|------|
| 必須修正 | 明確な要件違反、または発生条件・影響から対処の必要性が確認できる不具合、安全性・データ整合性などの問題。 |
| 任意改善 | 現在の要件達成を妨げず、修正負担に見合う実用的な効果がある改善。 |
| 対応不要 | 前提が成立しない、既存の保証で対処済み、要件外、主観的な好み、または効果が修正負担に見合わない提案。 |

指摘を生成する場合は、必須修正または任意改善と評価した問題を報告対象にする。
評価には、判断を支える発生条件・影響・既存の保証などの根拠を簡潔に添える。
