# simple-design-doc

確定済みの内容だけを design doc にまとめる。
設計判断そのものは行わない。

## 参照先

- `references/design-doc-template.md`: design.md を読む、または書く直前に読む。

## 必須制約

- ユーザーへの質問、設計案の比較、decision の確定を行わない。
- template の section ownership で書き手が `simple-design-doc` のセクションだけを書く。
- `## 決定事項` にない判断を `## 結論` や `## 設計` に持ち込まない。
- 未解決の設計判断、決定事項同士の矛盾、要件を満たさない箇所を見つけた場合は、推測で埋めずに一覧にして呼び出し元の `grill-design` へ戻す。単独起動の場合は一覧をユーザーへ示し、`grill-design` で決めるよう提案して停止する。

## Workflow

### Step 1: 確定済みの内容を読む

design.md があれば全文を読む。
単独起動で design.md が無い場合は、会話とチケットから要件と確定済みの判断を抽出し、template に従って design.md を作成する。
このとき会話で合意されていない判断は `## 決定事項` に書かない。

### Step 2: 整合性を確認する

要件、決定事項、用語、スライスの間の矛盾と未解決の判断を確認する。
見つかった場合は必須制約に従って戻す。

### Step 3: 書く

template の文体に従い、`## 結論`、`## 設計`、`## リスク` を書く。
書いた後、template の文体の最後の確認を行い、不要なセクションを削る。

## Report

design.md の path、書いたセクション、戻した未解決の判断を報告する。
