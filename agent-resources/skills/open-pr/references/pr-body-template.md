# PR Body Template

PR body を新規作成・更新する前にこの reference を読む。
リポジトリに `.github/pull_request_template.md` またはより具体的なローカル PR 規約がない場合、下の template を使う。
プラン、チケット、動作確認結果から、PR本文に必要な内容だけを抽出する。

## PR descriptionの書き方

- 「何を変更したか」と「レビュアーが見るべき点」に絞る。実装の手順を逐一説明しない。
- Design docへのリンクを貼り、設計の詳細はそちらに譲る。PR本文に重複させない。
  - ユーザーからURLを共有されていない場合、なにを記載するかユーザーに確認する
- 実装ファイルの一覧など、diffを見れば分かる情報は書かない。

```markdown
## チケット
<指定されたチケットの URL>

## 概要
<この PR で何を変更したか（1〜3行）>

## Design doc
<設計の詳細を記載した Design doc の URL>

## レビュー観点
- <レビュアーが確認すべき挙動・設計判断・懸念点>

## テスト
- <実行したテストと結果>
```
