# Gates

Step 4 の self-check から、G1、AI レビュー、G2 までに使う。
sliced では、対象スライスと全体の `## 要件`・`## 決定事項`・`## 設計` を対象にする。

## self-check

G1 の前に、ユーザーへ確認せずに次を確認する。
満たさない項目は plan.md を直してから G1 へ進む。
直すために新しいユーザー判断が必要な場合は、`decisions.md` の質問ラウンドで決める。

- `## 未決事項` が無い。
- 全受入基準（sliced では対象スライスの delivers）が、いずれかのタスクの `implements` に含まれる。
- `## 変更面` の各項目を実装するタスクがある。
- `decisions.md` の「ユーザーに聞く判断」に当たる判断を、AI判断にしていない。
- 各受入基準の振る舞いを、`## テスト方針` と各タスクの `test` が検証する。
- `## まれなケースの扱い` の各項目が、`decisions.md` の「まれなケース」の基準を満たす。
- plan.md だけを読む fresh session が、entry point、既存 pattern、`done_when` から実装を進められる。

## G1: 内容の理解と AI レビューの実行可否

G1 では、ユーザーが「何を、なぜ、どう変えるか」と主なリスク・テストを理解したうえで、AI レビューを実行するかを判断できるようにする。
G1 では承認も実装開始も扱わない。
タスク一覧は示さない。
チャット上に30行程度で次を示す。

```text
## 実装プランの確認（G1）

**何を**: <ゴール1行> — AC1 <...>, AC2 <...>
**なぜこの方法か**:
- D1 <ユーザー判断>: <決定>
- A1 <AI判断>: <決定> — <根拠>
**どう変えるか**: <設計の要点を2〜4行>
**変更面**: <面と変更内容。無ければ なし>
**展開順**: <該当する場合だけ>
**まれなケースの扱い**: <該当する場合だけ>
**主なリスク**: <最大3件と手当て>
**テスト**: <確かめる振る舞い>
**AIレビュー**: <reviewer / model / effort> — 観点: <この plan で特に見る点>

plan: <plan.md の絶対パス>

→ 修正 / AIレビューを実行 / AIレビューを見送って G2 へ
```

AI判断は、ユーザーが異論を持ちうるものを優先して示す。
同じ対象の2回目以降の AI レビューでは、再レビューの理由と前回からの変更点も示す。
reviewer / model / effort は `../../ai-review/references/reviewer-policy.md` に従って決める。

回答に応じて次を行う。

- 修正: plan.md に反映し、self-check からやり直す。新しいユーザー判断が生じた場合は、質問ラウンドで決めてからやり直す。
- AIレビューを実行: G1 の承認を ai-review の起動に対する同意として扱い、次の節に進む。
- AIレビューを見送る: `## AIレビュー` に `見送り: <理由>` を書き、G2 に進む。

## AI レビューの実行

`../../ai-review/SKILL.md` を読み、plan review mode で実行する。
reviewer には、G1 の修正を反映した最新の plan.md、元ソースの参照先または依頼の抜粋、調査した path と既存 pattern、`## AIレビュー` で見送り済みの指摘を渡す。
結果の実行設定、信頼性、指摘を `## AIレビュー` に書く。
`UNTRUSTED` または `BLOCKED` の場合は `../../ai-review/references/reviewer-policy.md` に従い、結果と原因を示して同じ reviewer を再実行するかを確認する。

## G2: 指摘の採否と最終承認

指摘がある場合は、全指摘を1件ずつ次の形で示す。

```text
## 指摘の採否と最終承認（G2）

reviewer: <reviewer / model / effort> — 信頼性: <TRUSTED など>

**F1 [P1]** <指摘の要約>
- 根拠: <reviewer が示した根拠>
- 推奨: 採用 | 見送り — <理由を1行>（反映案: <採用する場合の反映内容>）

---

**F2 [P3]** <...>

回答例: 「F1 採用、F2 見送り、承認して実装開始」
→ 各指摘の採否 ＋ 承認して実装開始 / 承認して引き継ぎ / 修正
```

- タスクについての指摘には、該当するタスクの内容と、反映した場合の変更前後を添える。
- 一括承認を受け付けない。採否が決まっていない指摘が残る場合は、その指摘だけを改めて聞く。
- 指摘が `decisions.md` の「ユーザーに聞く判断」に当たる新しい判断を求める場合は、採否で決めずに `## 未決事項` に加え、質問ラウンドで決める。
- 採用した指摘だけを plan.md に反映し、見送った指摘は理由とともに `## AIレビュー` に書く。
- 反映が反映案と異なる場合、または G1 で説明した内容が実質的に変わった場合は、変更点を示して再レビューするかを G1 と同じ形で確認し、最終承認は改めて聞く。

指摘が無い場合、または AI レビューを見送った場合は、G1 以降の変更点だけを示して最終承認を聞く。

最終承認を得たら、single では `Status: approved`、sliced では対象スライスを `approved` にし、選ばれた経路で SKILL.md の Step 6 に進む。
